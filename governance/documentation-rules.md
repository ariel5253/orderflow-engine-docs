# Documentation rules

These rules are enforced by `check-docs.mjs` in the `orderflow-engine-tools` repository, which reads its configuration from [docs-governance.json](docs-governance.json). Any rule the check cannot automate is marked *(review)*.

## 1. Principles

| # | Rule |
|---|------|
| DR-1 | Each document answers **one question**. That question is recorded in the document map |
| DR-2 | A document that is not in the map does not exist. The check fails on any unindexed Markdown file |
| DR-3 | Tables come before prose. Short sentences, no filler *(review)* |
| DR-4 | Every claim is falsifiable: it links to a test, a command or a file *(review)* |
| DR-5 | No duplication. A fact lives in one document, and other documents link to it *(review)* |
| DR-6 | A document changes in the same task that changes the behavior it describes |

## 2. Languages

| Audience | Language | Files |
|----------|----------|-------|
| Delivery: repository READMEs and the ADR | English **and** Spanish, equivalent content | `name.md` + `name.es.md` |
| Internal technical: SPEC, TASKS, plan, contract, data model, architecture, governance, handoff | English only | `name.md` |

The two files of a pair must have the same number of headings.

## 3. Locations

Markdown files are allowed only in these locations. The root of each folder holds only its READMEs and its license.

| Location | Content | Language |
|----------|---------|----------|
| `<folder>/README(.es).md` | Purpose, how to run, links to the document map | en + es |
| `orderflow-engine-api/docs/adr/` | The ADR, which travels with the deliverable repository | en + es |
| `orderflow-engine-docs/handoff/` | The verified state and how to resume | en |
| `orderflow-engine-docs/spec/` | Constitution, SPEC, plan, TASKS, API contract, data model, architecture | en |
| `orderflow-engine-docs/governance/` | These rules and the templates | en |

Non-Markdown material has fixed homes as well:

| Folder | Content | Edited by hand? |
|--------|---------|-----------------|
| `orderflow-engine-docs/assignment/` | The original assignment | No |
| `orderflow-engine-docs/diagrams/` | SVG figures named `NN-kebab-name.svg`, numbered by first appearance | No. They are generated by `orderflow-engine-tools/diagrams`, which also checks them for collisions |
| `orderflow-engine-docs/handoff/progress.svg` | The task progress chart | No. It is generated from the HANDOFF task table by `orderflow-engine-tools/progress`, and `check-docs` fails when it is stale |
| `orderflow-engine-docs/deliverables/` | Word and PDF versions of the ADR, in English and Spanish, and `manifest.json` with the SHA-256 of each source | No. They are generated by `orderflow-engine-tools/render`, and `check-docs` fails when a source changed after its deliverable was built |

**Required headings.** `docs-governance.json` lists the headings that a document must contain, such as the four topics the assignment requires in the API README and the four A3 items in the ADR. The check fails when one is missing.

## 3a. Print template (Word and PDF)

Every Word or PDF document follows one template, applied by `orderflow-engine-tools/render`:

| Element | Rule |
|---------|------|
| Page | A4, 2 cm margins |
| Font | Arial 12 for every text, tables included |
| Color | Black only. No colored titles |
| Headings | Bold, same size, separated by spacing |
| Tables | Thin black borders. Column widths follow content, and no column is narrower than its longest word |
| Footer | The source path and the page number, in the document's language |
| Page limit | The ADR fits on one page (the assignment's limit). The build fails otherwise |

## 4. Front matter

Every document in `orderflow-engine-docs` and `orderflow-engine-api/docs`, except the READMEs, starts with:

```yaml
---
id: <stable id, e.g. SPEC, ADR-0001>
title: <title>
status: draft | proposed | accepted | rejected | deprecated | superseded | template
lang: en | es
pair: <relative path to the other-language file> | none
last-reviewed: YYYY-MM-DD
---
```

- `lang` must match the file name: a file ending in `.es.md` is `es`.
- `pair` must resolve to an existing file.

## 5. Naming and links

| Rule | Example |
|------|---------|
| kebab-case file names | `data-model.md` |
| ADRs are numbered with four digits, and numbers are never reused | `docs/adr/0001-order-pricing-and-confirmation.md` |
| Links are relative and never leave their repository. Other repositories are cited by name, without a link. The check verifies both rules | `[SPEC](../spec/SPEC.md)` |

## 6. Architecture decision records

- **One ADR.** The assignment asks for one ADR of at most one page, so the delivery has exactly one: `orderflow-engine-api/docs/adr/0001-order-pricing-and-confirmation(.es).md`. Rejected alternatives for each technical decision are listed in [plan.md](../spec/plan.md).
- **Format:** the header table of MADR 4.0.0 (status, date, decision makers, confidence), a short context, and the four sections the assignment requires:
  - decisions and discarded alternatives
  - what was not implemented, on purpose
  - the code review checklist
  - risk and mitigation

  Use [templates/adr-template.md](templates/adr-template.md).
- **Lifecycle:** `proposed` → `accepted` | `rejected`, and later `deprecated` | `superseded`. An accepted ADR is never rewritten. A new ADR supersedes it.
- **Length:** at most 500 words per language file, which is one page.

## 7. Internationalization resources

The same check verifies that every locale file under an `i18n` folder has exactly the same keys as its siblings, with no empty values. This covers `.properties` bundles and `.json` dictionaries.
