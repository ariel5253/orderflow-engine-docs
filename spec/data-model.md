# Orderflow Engine — Data model

> **Question this document answers:** which tables, constraints, indexes and locks hold the invariants of the [specification](SPEC.md), and why is the model in third normal form?

PostgreSQL, with Liquibase changelogs in `orderflow-engine-api/src/main/resources/db/changelog/` (T-08). Figure: [diagrams/08-data-model.svg](../diagrams/08-data-model.svg).

| Convention | Rule |
|------------|------|
| Names | Plural `snake_case` tables |
| Identity | Tenant-scoped tables use the composite primary key `(tenant_id, id)`. Every foreign key between tenant-scoped tables includes `tenant_id` |
| Ids | `uuid`, generated by the application as UUIDv7, so inserts stay local in the index |
| Money | `numeric(19,4)`, read back at the currency scale |
| Rates and percentages | `numeric(7,6)` with `CHECK` between 0 and 1 |
| Time | `timestamptz NOT NULL` |
| JSON | None. Every fact is a column, so every fact can be constrained and queried |

## 1. Reference data

| Table | Columns | Keys and checks |
|-------|---------|-----------------|
| `currencies` | `code` char(3), `scale` smallint | PK `code`. `CHECK scale BETWEEN 0 AND 4`. Seeds: COP (0), USD (2) |
| `countries` | `code` char(2), `currency_code`, `rounding_mode`, `gift_tax_policy`, `quote_ttl` interval | PK `code`. FK → `currencies`. `CHECK` on `rounding_mode` and on `gift_tax_policy IN ('EXEMPT','TAXED')`. Seeds: CO, EC |
| `tenants` | `id` text, `country_code`, `brand` | PK `id`. FK → `countries`. `UNIQUE (country_code, brand)`. Seeds: `co-alpha`, `ec-alpha` |

Scale belongs to the currency. Rounding mode and gift tax policy are fiscal policy of the country, so two countries sharing a currency may still round differently.

## 2. Catalog and levers (tenant-scoped)

| Table | Columns | Keys and checks |
|-------|---------|-----------------|
| `customers` | `tenant_id`, `id`, `name` | PK `(tenant_id, id)` |
| `families` | `tenant_id`, `code` | PK `(tenant_id, code)` |
| `products` | `tenant_id`, `id`, `sku`, `name`, `family_code`, `tax_rate`, `list_price` | PK `(tenant_id, id)`. `UNIQUE (tenant_id, sku)`. FK `(tenant_id, family_code)` → `families` |
| `tier_rules` | `tenant_id`, `id`, `product_id` NULL, `family_code` NULL, `active` | PK `(tenant_id, id)`. `CHECK` exactly one target. Composite FKs to `products` and `families`. Partial unique indexes `(tenant_id, product_id) WHERE active` and `(tenant_id, family_code) WHERE active`: one active rule per target (BR-02) |
| `tier_brackets` | `tenant_id`, `tier_rule_id`, `from_qty`, `percent` | PK `(tenant_id, tier_rule_id, from_qty)`. `from_qty ≥ 1` |
| `combo_rules` | `tenant_id`, `id`, `combo_price`, `active` | PK `(tenant_id, id)`. Evaluated in id order (SPEC BR-03) |
| `combo_items` | `tenant_id`, `combo_rule_id`, `product_id`, `min_qty` | PK `(tenant_id, combo_rule_id, product_id)`. `min_qty ≥ 1` |
| `gift_rules` | `tenant_id`, `id`, `trigger_product_id` NULL, `trigger_family_code` NULL, `min_qty` NULL, `min_gross` NULL, `gift_product_id`, `gift_qty`, `repeatable`, `active` | PK `(tenant_id, id)`. `CHECK` that exactly one trigger is set: product or family with `min_qty`, or `min_gross` alone. `gift_qty ≥ 1` |

The assignment says each SKU has a rate, so the rate is a column of the product. Tax categories and price history are not modeled (ADR-0001, "Not implemented").

## 3. Credit

| Table | Columns | Keys and checks | Invariant |
|-------|---------|-----------------|-----------|
| `credit_accounts` | `tenant_id`, `customer_id`, `credit_limit`, `consumed` | PK `(tenant_id, customer_id)`, FK → `customers`. `CHECK (consumed >= 0 AND consumed <= credit_limit)` | The limit can never be exceeded, even if application code is wrong |
| `credit_ledger` | `tenant_id`, `order_id`, `amount` | PK `(tenant_id, order_id)`, FK → `orders` (RESTRICT). `amount > 0`. Append-only | Each order consumes credit at most once, and `consumed = Σ amount` |

## 4. Quotes and orders

| Table | Columns | Keys and checks | Invariant |
|-------|---------|-----------------|-----------|
| `quotes` | `tenant_id`, `id`, `customer_id`, `currency_code`, `payment_method`, `created_at`, `expires_at` | PK `(tenant_id, id)`. `UNIQUE (tenant_id, id, customer_id)` (target of the order FK). FK → `customers`, → `currencies`. `CHECK payment_method IN ('CASH','CREDIT')`. Index `(expires_at)` for the purge | **Insert-only.** No UPDATE statement exists for quotes |
| `quote_lines` | `tenant_id`, `quote_id`, `line_no`, `product_id`, `gift_rule_id` NULL, `qty`, `unit_price`, `tax_rate`, `taxable_base`, `tax` | PK `(tenant_id, quote_id, line_no)`. FK → `quotes` (ON DELETE CASCADE), → `products`, → `gift_rules`. `qty ≥ 1` | A gift line has `gift_rule_id`, and its `unit_price` is the list price used as reference value |
| `quote_line_adjustments` | `tenant_id`, `quote_id`, `line_no`, `kind`, `rule_id`, `amount` | PK `(tenant_id, quote_id, line_no, kind, rule_id)`. FK → `quote_lines` (ON DELETE CASCADE). `CHECK kind IN ('TIER','COMBO')`. `amount > 0`: a component that rounds to zero is not emitted | One row per discount component of a line, already rounded (RP-2). `rule_id` is a captured origin label, not a FK, because rules are deactivated rather than deleted |
| `orders` | `tenant_id`, `id`, `quote_id`, `customer_id`, `order_number`, `confirmed_at` | PK `(tenant_id, id)`. `UNIQUE (tenant_id, quote_id)`. `UNIQUE (tenant_id, order_number)`. FK `(tenant_id, quote_id, customer_id)` → `quotes` (RESTRICT). Index `(tenant_id, customer_id, confirmed_at DESC)` for the history | **No breakdown amounts.** The order points at its sealed quote, so every breakdown figure exists exactly once |

- **Quote state is derived:**
  - `CONFIRMED` when an order exists for the quote
  - otherwise `EXPIRED` when `now > expires_at`
  - otherwise `OPEN`
- **Order numbers** come from one sequence per country, `order_number_seq_<country>`, formatted as `CO-000042`. Numbers are drawn inside the order transaction, so a rollback leaves a gap. Gaps are acceptable. Duplicates are not: the per-country sequence prevents them across tenants, and `UNIQUE (tenant_id, order_number)` within a tenant. The constraint includes `tenant_id`, so it stays valid if tables are partitioned by tenant.

## 5. Idempotency and outbox

| Table | Columns | Keys and checks | Invariant |
|-------|---------|-----------------|-----------|
| `idempotency_keys` | `tenant_id`, `customer_id`, `idem_key`, `request_hash`, `order_id` NULL, `response_body` bytea, `created_at` | PK `(tenant_id, customer_id, idem_key)`. `UNIQUE (tenant_id, order_id)`. FK `(tenant_id, order_id)` → `orders` (RESTRICT). Index `(created_at)` for the purge | One owner per key. A concurrent duplicate blocks on the uncommitted row |
| `outbox_events` | `tenant_id`, `id`, `order_id`, `destination`, `status`, `attempts`, `next_attempt_at`, `locked_until` NULL, `last_error`, `created_at` | PK `(tenant_id, id)`. FK `(tenant_id, order_id)` → `orders` (RESTRICT). `UNIQUE (tenant_id, order_id, destination)`. `CHECK destination IN ('PUSH','ERP')`. `CHECK status IN ('PENDING','SENT','DEAD')`. Partial indexes: `(next_attempt_at) WHERE status = 'PENDING'` and `(created_at) WHERE status = 'SENT'` | Written in the order transaction (P-04). One event per destination per order. The `id` is the `event_id` that consumers deduplicate on |

An event is **leased** while `status = 'PENDING' AND locked_until > now()`. The payload is built at send time from the order and its quote, which are immutable.

## 6. How the breakdown is read

The API breakdown (SPEC §8) is rendered from `quote_lines` and `quote_line_adjustments`. Exact arithmetic is derived when the breakdown is read. Values that needed a rounding or policy decision are stored.

| Value | Source |
|-------|--------|
| `description` | `products.name` (current name, not captured) |
| `isGift`, gift `origin` | `gift_rule_id IS NOT NULL`, rendered as `GIFT:<gift_rule_id>` |
| `unitPrice` | `unit_price`, or 0 for a gift line (whose stored `unit_price` is the reference list price) |
| `gross` | `qty × unit_price`, or 0 for a gift line |
| `discounts[]` of a line | Adjustments with `kind = 'TIER'` |
| `comboAllocations[]` | Adjustments with `kind = 'COMBO'` |
| `net` | `gross − Σ adjustments` |
| `referenceValue` | `qty × unit_price` of a gift line |
| `taxableBase`, `tax` | Stored per line |
| Order totals | Sums of the line values. Order-level `discounts[]` are grouped by `(kind, rule_id)`, and `gifts[]` are the gift lines |

## 7. Third normal form

All non-key columns depend on the whole key and on nothing else in their table. The few columns that look derived are deliberate, and each has a reason:

| Column | Why it is stored |
|--------|------------------|
| `tenant_id` in every tenant-scoped key | A deliberate tenant discriminator. Ids are UUIDs, so `id` alone would identify a row. `tenant_id` is still kept in every key and pinned by every composite FK, so no row can reference another tenant's data, and tables can be partitioned by tenant later |
| `quote_lines.unit_price`, `tax_rate`; `quotes.currency_code`, `expires_at` | Captured facts: the values in force at quote time T. They are not copies of current catalog data, which may change afterwards |
| `quote_lines.taxable_base`, `tax` | The result of the country policy, scale and rounding at T. Recomputing them later is unsafe, so the agreed amounts are stored |
| `credit_accounts.consumed` | A materialized `Σ credit_ledger.amount`, updated in the same transaction. It is the concurrency guard: its `CHECK` is the invariant. `CreditLimitIT` asserts the equality |
| `credit_ledger.amount` | The audit record of the credit movement behind `consumed = Σ amount`. Today it equals the order's quote total, and `CreditLimitIT` asserts that. A future release movement would have no quote |
| `outbox_events.created_at` | The event row's own timestamp, used by the retention index. It is not read as the order's time |
| `orders.customer_id` | Needed for the history index. It is pinned by the FK `(tenant_id, quote_id, customer_id)`, so it can never disagree with the quote |
| `idempotency_keys.response_body` | The replay contract requires a byte-identical response |

## 8. Locks taken by the confirmation

Locks are always taken in the same order: **idempotency key → quote → credit account** (SPEC §7.1).

| Step | Statement | Lock |
|------|-----------|------|
| 1 | `INSERT … ON CONFLICT DO NOTHING` on `idempotency_keys` | Unique-index entry, held until commit |
| 2 | `SELECT … FROM quotes WHERE … FOR UPDATE`, then check that no order exists for it and that it has not expired | Row lock on the quote |
| 3 | `UPDATE credit_accounts SET consumed = consumed + ? WHERE … AND consumed + ? <= credit_limit` | Row lock on the credit account |
| 4–6 | Inserts into `orders`, then `credit_ledger` (it references the order) and `outbox_events`, then the order id and response on the key | New rows only |

`lock_timeout` is set for the transaction. If it expires, the API answers 409 instead of hanging.

## 9. Scalability

| Lever | How the model supports it |
|-------|---------------------------|
| Partitioning or sharding | `tenant_id` leads every tenant-scoped key and FK, so tables can be partitioned by tenant (LIST or HASH), or sharded with co-located joins, without re-keying |
| Write contention | The only shared hot row is one customer's credit account (RISK-01). Quotes, lines and orders are insert-only |
| Growth | Unconfirmed quotes are purged after `expires_at` + 7 days, and their lines and adjustments go with them (ON DELETE CASCADE). A confirmed quote cannot be purged: `orders → quotes` is RESTRICT. Sent events and idempotency keys are purged by retention |
| Cross-tenant jobs | The relay and the purge use the indexes that do not start with `tenant_id`: `expires_at`, `created_at`, and the partial outbox indexes |
| Relay throughput | Claims use `FOR UPDATE SKIP LOCKED` with a lease, so several relay instances can run at once |
| Reads | Catalog reads may use replicas. Order reads stay on the primary (I-201) |

## 10. Notes

| Code | Note |
|------|------|
| DM-01 | Price scale is validated when prices are loaded, and by a test over the seeds. A database `CHECK` cannot read the currency's scale without a trigger, and a trigger is not worth it for seeded data |
| DM-02 | Quotes, quote lines and adjustments are insert-only. The repository has no UPDATE statement for them, and `QuotePersistenceIT` checks it |
| DM-03 | The order references the quote instead of copying it. Every breakdown figure exists once, so quote and order cannot diverge (G-1). The only other amount, `credit_ledger.amount`, is an audit record checked against the quote total |
